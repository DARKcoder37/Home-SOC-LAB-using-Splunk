# Phase 2 — Splunk Enterprise Installation

## 1. Overview

The second phase of the Splunk SOC Home Lab focuses on preparing the Ubuntu Desktop virtual machine for Splunk Enterprise, verifying the required system resources, installing Splunk, and validating that the service is operational.

Splunk Enterprise will serve as the Security Information and Event Management (SIEM) platform for collecting, searching, and analyzing security logs generated by the lab endpoints.

### Objectives

- Verify the Ubuntu operating system and check available storge.
- Configure VirtualBox network adapters for isolated lab communication and internet connectivity.
- Download and install Splunk Enterprise.
- Configure Splunk to start automatically.
- Access and validate the Splunk Web interface.

## 2. Lab Environment

The installation is performed on the Ubuntu Desktop virtual machine created during Phase 1.

| Component | Configuration |
|---|---|
| Virtualization platform | Oracle VirtualBox |
| Guest operating system | Ubuntu Desktop 22.04.5 LTS |
| System architecture | x86-64 |

Ubuntu 22.04 LTS on x86-64 is listed as a supported platform in the applicable Splunk Enterprise system requirements. Refer to the official [Splunk Enterprise System Requirements](https://help.splunk.com/en/splunk-enterprise/administer/install-and-upgrade/10.6/plan-your-splunk-enterprise-installation/system-requirements-for-use-of-splunk-enterprise-on-premises).

## 3. VirtualBox Network Configuration

The Ubuntu VM uses two network adapters for different purposes. This configuration allows the VM to communicate with other lab machines while providing internet access when required.

### 3.1 Adapter 1 — Internal Network (`SOC-LAB`)

Adapter 1 is used for communication between the Ubuntu VM and the other virtual machines in the isolated SOC lab.

**Configuration:**

- Enable Network Adapter: Checked
- Attached to: `Internal Network`
- Name: `SOC-LAB`
- Cable Connected: Checked
- Ubuntu lab IP address: `192.168.50.30/24`

**Figure 1: [View Adapter 1 — Internal Network configuration](screenshots/adapter-1-internal-network.png)**

### 3.2 Adapter 2 — NAT

Adapter 2 provides internet connectivity through the host machine. It is used when downloading Splunk Enterprise, installing packages, or performing system updates.

**Configuration:**

- Enable Network Adapter: Checked when internet access is required
- Attached to: `NAT`
- Cable Connected: Checked

**Figure 2: [View Adapter 2 — NAT configuration](screenshots/adapter-2-nat.png)**

### 3.3 Adapter Usage and Security

Enable or disable network adapters according to the current task. Use Adapter 1 (`SOC-LAB`) for communication between lab VMs and Adapter 2 (`NAT`) for internet connectivity. When an adapter is not required, disable it.

This approach helps limit unnecessary connectivity and preserves the separation between the isolated lab network and internet access. Disabling NAT does not replace the need to review the guest operating system's routing and firewall configuration.

## 4. Prerequisites and System Verification

Before installing Splunk Enterprise, verify the Ubuntu version, system architecture, available disk space, memory, and internet connectivity.

### 4.1 Verify the Ubuntu Version

Open the Ubuntu terminal and run:

```bash
cat /etc/os-release
```

Alternatively, run:

```bash
lsb_release -a
```

The output should identify Ubuntu 22.04 LTS. For example:

```text
PRETTY_NAME="Ubuntu 22.04.5 LTS"
VERSION_ID="22.04"
```

The exact patch-level release may vary depending on installed updates.

**Figure 3: [View Ubuntu version verification](screenshots/ubuntu-version.png)**

### 4.2 Verify System Architecture

Run:

```bash
uname -m
```

Expected output:

```text
x86_64
```

This confirms that the operating system is running on a 64-bit x86 architecture.

**Figure 4: [View Ubuntu system architecture](screenshots/ubuntu-architecture.png)**

### 4.3 Check Available Storage

Splunk requires disk space for its application files, configuration, indexes, and collected logs.

For this home lab, **20 GB of free space is a practical starting estimate for installation and basic testing**, not a guaranteed official minimum. Actual storage requirements depend on the Splunk release, log ingestion volume, and data-retention period. Additional space may be needed as data accumulates.

Run the following command to check the root filesystem:

```bash
df -h /
```

Example output:

```text
Filesystem      Size  Used  Avail  Use%  Mounted on
/dev/sda5        39G   14G    24G   38%   /
```

Review the following fields:

- `Size`: Total filesystem capacity.
- `Used`: Space currently occupied.
- `Avail`: Space available for installation and future data.
- `Use%`: Percentage of filesystem capacity currently used.

To display all mounted filesystems, run:

```bash
df -h
```

**Figure 5: [View available storage](screenshots/ubuntu-storage.png)**

### 4.4 Check Disk Layout

Run:

```bash
lsblk
```

This command lists detected block devices, partitions, and their mount points. Use it alongside `df -h` to understand the disk layout and identify the filesystem mounted at `/`.

**Figure 6: [View Ubuntu disk layout](screenshots/ubuntu-disk-layout.png)**

### 4.5 Check Available Memory

Run:

```bash
free -h
```

Review the total and available memory to confirm that the VM has sufficient resources for the intended lab workload.

**Figure 7: [View available memory](screenshots/ubuntu-memory.png)**

### 4.6 Verify Internet Connectivity

Enable Adapter 2 (NAT) if internet access is required. Then run:

```bash
ping -c 4 archive.ubuntu.com
```

Successful replies confirm connectivity to the Ubuntu package archive.

If the hostname cannot be resolved, check DNS configuration. If the command fails entirely, verify the NAT adapter and the guest's network configuration.

**Figure 8: [View internet connectivity verification](screenshots/internet-connectivity.png)**

## 5. Download Splunk Enterprise

### 5.1 Access the Official Download Page

1. Open the official [Splunk Enterprise Download Page](https://www.splunk.com/en_us/download/splunk-enterprise.html).
2. Sign in or create a Splunk account if required.
3. Select the Linux installation package for the appropriate 64-bit architecture.
4. Confirm that the selected release is compatible with Ubuntu 22.04 LTS.
5. Download the Debian package (`.deb`) to the Ubuntu VM.

Use the official Splunk download source to obtain the installation package.

**Figure 9: [View Splunk Enterprise download page](screenshots/splunk-download.png)**

### 5.2 Locate the Downloaded Package

Open a terminal and run:

```bash
ls -lh ~/Downloads
```

Confirm that the downloaded Splunk Enterprise `.deb` package is present.

**Figure 10: [View downloaded Splunk package](screenshots/splunk-package.png)**

## 6. Install Splunk Enterprise

### 6.1 Install the Debian Package

Navigate to the download directory:

```bash
cd ~/Downloads
```

Identify the exact package filename:

```bash
ls -lh splunk*.deb
```

Install the package using its actual filename:

```bash
sudo dpkg -i ./splunk-<downloaded-version>-linux-amd64.deb
```

Replace the placeholder with the exact filename shown in the Downloads directory. Do not enter the angle-bracketed placeholder literally.

The `dpkg -i` command installs a local Debian package. If the installation reports missing dependencies, review the error before attempting to resolve it.

**Figure 11: [View Splunk Enterprise package installation](screenshots/splunk-installation.png)**

### 6.2 Start Splunk for the First Time

After installation, run:

```bash
sudo /opt/splunk/bin/splunk start --accept-license
```

Follow the on-screen instructions to complete the initial startup and create the administrator credentials if prompted.

Use a strong password and do not include credentials in screenshots or repository documentation.

**Figure 12: [View initial Splunk startup](screenshots/splunk-first-start.png)**

### 6.3 Enable Splunk to Start at Boot

Configure Splunk to start automatically when Ubuntu boots:

```bash
sudo /opt/splunk/bin/splunk enable boot-start
```

Review the command output for errors. If successful, Splunk is configured for automatic startup according to its boot-start configuration.

**Figure 13: [View Splunk boot-start configuration](screenshots/splunk-boot-start.png)**

Log in using the administrator credentials created during the initial startup.

## 8. Installation Validation

### 8.1 Check Splunk Status

Run:

```bash
sudo /opt/splunk/bin/splunk status
```

Review the output and confirm that Splunk is running.

### 8.2 Verify the Splunk Process

Run:

```bash
pgrep -a splunkd
```

A running `splunkd` process provides additional evidence that the Splunk daemon is active.

### 8.3 Verify the Web Port

Run:

```bash
sudo ss -lntp | grep ':8000'
```

If Splunk Web is listening on its default port, the output should show a listening socket associated with port `8000`.

**Figure 16: [View Splunk service and process verification](screenshots/splunk-status.png)**

## 9. Security Considerations

- **Network isolation:** Preserve the `SOC-LAB` internal network for communication between lab VMs.
- **Controlled internet access:** Use NAT for downloads when required, and disable unnecessary adapters when they are not needed.
- **Credential security:** Use a strong administrator password and never commit credentials to GitHub.
- **Service exposure:** Do not expose Splunk Web or management ports directly to the public internet.
- **Resource monitoring:** Monitor available storage and memory as logs are collected and indexed.
- **Trusted downloads:** Obtain Splunk installation packages only from the official Splunk website.
- **Authorized testing:** Use the SOC lab for security monitoring and testing on systems you own or are authorized to assess.

## 10. Troubleshooting Notes

### 10.1 Splunk Does Not Start

Check the status:

```bash
sudo /opt/splunk/bin/splunk status
```

Review the daemon log:

```bash
sudo tail -n 50 /opt/splunk/var/log/splunk/splunkd.log
```

Use the reported error to determine the next troubleshooting step.

### 10.2 Splunk Web Does Not Load

Check whether Splunk is listening on port `8000`:

```bash
sudo ss -lntp | grep ':8000'
```

Also confirm that the Ubuntu VM has the expected lab IP address and that the browser's machine can reach it.

### 10.3 Insufficient Disk Space

Check filesystem capacity:

```bash
df -h /
```

Review disk usage before removing files or changing the installation.

### 10.4 Internet Connectivity Fails

Check interfaces and routes:

```bash
ip -br addr
ip route
```

Confirm that Adapter 2 is enabled and attached to NAT when internet connectivity is needed. Also check DNS resolution and the Ubuntu network configuration.

### 10.5 Lab VM Connectivity Fails

Confirm that Adapter 1 is enabled and attached to the `SOC-LAB` Internal Network. Verify the static IP address and subnet mask inside Ubuntu.

When troubleshooting, inspect which adapter is enabled and avoid changing the static lab IP unnecessarily.
